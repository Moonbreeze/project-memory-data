# Canonical Doc

## Summary

Version 1 should prove transport compatibility and real token savings before attempting broad protocol innovation.

## Guidance

- The first MVP should preserve compatibility with target coding CLIs and must not break streaming or tool-use flows.
- Version 1 should emphasize deterministic and content-aware input compression before investing heavily in novel bidirectional intermediate languages.
- Output-side compacting and cheap-model expansion should be limited to plain final assistant prose in the MVP.
- Every transform in v1 should have an explicit bypass rule and a measurable success criterion.
- The MVP should produce instrumentation for token savings, latency, fallback rate, and semantic regressions so later iterations are evidence-driven.
