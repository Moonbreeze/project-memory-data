# Decision

## Context

3x-ui панель по умолчанию просит настроить TLS-сертификат (Let's Encrypt). Есть два пути: (a) домен + LE сертификат с auto-renew через порт 80, (b) LE для IP-адреса (новая фича LE, 6-дневный сертификат, порт 80 нужен открытым постоянно для renew), (c) отказ от публичного доступа к панели и использование SSH local port forwarding. Домена у проекта нет, регистрировать не хотелось. Публичный HTTP с паролем — неприемлемо, креды ходят в открытом виде.

## Decision

Панель 3x-ui слушает на `0.0.0.0:29486` внутри машины, но порт 29486 закрыт в ufw. Доступ только через SSH local port forward: `ssh -L 29486:127.0.0.1:29486 -N moonbreeze@147.45.196.137 -p 51218`. Порт 80 в ufw также закрыт, LE не используется.

## Consequences

- Плюс: панель не торчит в интернет вообще, атака на HTTP/пароль/WebBasePath невозможна. Аутентификация к panel наследует безопасность SSH ключа.
- Плюс: не нужен домен, DNS-записи, отслеживание истечения LE.
- Минус: для каждого админ-доступа нужно поднять SSH-сессию с `-L 29486:127.0.0.1:29486`. Мобильный доступ к панели практически отсутствует.
- Минус: 3x-ui в share-ссылках подставляет `127.0.0.1` вместо публичного IP (так как определяет адрес из URL панели). Нужно ручное редактирование ссылок при экспорте — зафиксировано в runbook add-client.
