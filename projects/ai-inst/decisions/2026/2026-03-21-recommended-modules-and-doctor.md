# Decision

## Context

При скаффолдинге нового проекта был забыт модуль testing — это обнаружилось только постфактум. Проблема системная: ничто не предупреждало о пропущенных базовых модулях. Рассматривались альтернативы: (1) обязательные модули, которые подключаются автоматически и не могут быть удалены, (2) шаблоны проектов с предзаполненным .ai-modules, (3) рекомендованные модули с мягкой проверкой (doctor). Обязательные модули слишком жёсткие — разные проекты имеют разные потребности. Шаблоны решают только момент init, но не помогают при добавлении новых рекомендаций к существующим проектам.

## Decision

Добавлена система рекомендованных модулей: файл recommended в rules repo содержит список базовых модулей, команда project doctor проверяет их наличие в проекте и предупреждает о пропущенных. Doctor автоматически запускается при project init. CLI-команды recommend list/add/rm управляют списком, MCP-инструменты project_doctor, recommend_list/add/rm обеспечивают доступ из агентов. Подход мягкий (warning, не error) — пользователь сам решает, добавлять ли модуль.

## Consequences

- Новые проекты получают предупреждение о пропущенных базовых модулях при init
- Существующие проекты можно проверить через ai-inst project doctor в любой момент
- Добавление нового рекомендованного модуля влияет на все проекты при следующем запуске doctor — масштабируемо
- Мягкая модель (warning) не ломает обратную совместимость и не навязывает модули проектам с особыми требованиями
- Текущий рекомендованный набор: workflow, testing
